# COMFORT 36

Vite + React + TypeScript. Лендинг, отдельная страница корзины и страница конфиденциальности. Каталог использует карточки из ВК Маркета. Видео в галерее загружается при открытии ролика.

```sh
npm ci
npm run dev
npm run build
```

Для обновления GitHub Pages запустите `npm run deploy`. Команда собирает сайт с базовым путём `/comfort36-landing/` и добавляет коммит в `gh-pages`. Ветки `backup-source-2026-11-23` и `backup-pages-2026-11-23` содержат предыдущие исходники и опубликованную сборку. Для отката содержимого Pages восстановите снимок из второй ветки в `gh-pages`.

## Заявки и отчёт

### Отправка с сайта в ВК

Для Рег.ру «Хост-0» предусмотрен [PHP-обработчик и порядок переключения с сохранением старого сайта](integrations/reg-ru/README.md). В сборке без адреса API сайт показывает способы связи. Однокликовая отправка включается при сборке с переменной `VITE_LEAD_API_URL`. В этом режиме все формы передают заявку на сервер, а страница «Спасибо» открывается после записи в очередь. Исправления контактов отправляются в тот же диалог с номером исходной заявки.

1. На VPS или облачном сервере Рег.ру в России запустите один экземпляр `integrations/lead-intake.mjs` под Node.js 24 с автоматическим перезапуском. Укажите `LEAD_DB_PATH` на постоянном локальном диске с доступом только у сервисного пользователя.
2. Включите сообщения сообщества ВК и выпустите ключ сообщества с доступом к сообщениям. Сохраните его в серверном окружении как `VK_COMMUNITY_TOKEN`. Попросите заказчика открыть диалог с сообществом и отправить ему сообщение либо добавьте бота в закрытую рабочую беседу. В `VK_PEER_ID` укажите `peer_id` из диалога или из события бота в беседе. Номер беседы из адресной строки может отличаться от идентификатора, который видит бот. При необходимости задайте `VK_API_VERSION` (по умолчанию `5.199`).
3. Выставьте `LEAD_ORIGIN=https://goodrojh.github.io` для текущего предпросмотра. Настройте HTTPS для поддомена API и передавайте `POST` и `OPTIONS` с пути `/leads` на `http://127.0.0.1:8788/leads`. Прокси должен перезаписывать заголовок `X-Real-IP` фактическим адресом клиента и ограничивать частоту запросов. Сервис слушает локальный порт, который можно изменить через `LEAD_PORT`. Тела запросов и секреты не записываются в журналы.
4. Утвердите у оператора реквизиты и тексты политики и согласия для нового сценария. Опубликуйте фронтенд с `VITE_LEAD_API_URL=https://<поддомен>/leads` (эта переменная публичная). Проверьте тестовую заявку с главной, из корзины и из конфигуратора, получение сообщения и исправление телефона. Заявки отображаются в выбранном рабочем диалоге от имени сообщества. Заказы, оформленные в самом ВК Маркете, по-прежнему появляются в списке заказов ВК.

Сервер подтверждает приём после записи в SQLite. VK и отчёт отправляются отдельными задачами с повтором при ошибках. Просматривайте журнал сервиса на ошибки доставки. Текст заявки в очереди удаляется из неё при успешной отправке или через семь дней после приёма.

Для параллельного отчёта сайта добавьте в серверное окружение `SHEETS_WEB_APP` и `SHEETS_KEY` из настроек ниже. `UTM_ALLOWLIST_JSON` принимает список разрешённых значений. Таблица получает только дату, канал, случайный ID и разрешённые метки. Исправления не добавляют новые строки отчёта.

### Отчёт по событиям из ВК

Для отчёта по полученным событиям ВК подготовлены `integrations/vk-relay.mjs` и `integrations/GoogleSheets.gs`. В отчёте дата по Москве, канал и разрешённые метки кампаний. Имена, телефоны, профили, сообщения и адреса из ВК в отчёт не передаются. Заказы ВК Маркета фиксируются отдельным каналом, без меток, поскольку событие ВК их не передаёт.

1. В целевой Google Таблице откройте **Расширения → Apps Script**. Вставьте `GoogleSheets.gs` и запустите `setupComfort36` один раз. Получится лист «Лиды» с фильтром и закреплённым заголовком.
2. В настройках проекта создайте Script Property `SHEETS_KEY` с длинным случайным секретом. Опубликуйте скрипт как веб-приложение от имени владельца с доступом для запросов без входа. Секрет проверяется при каждом POST. Скопируйте URL с окончанием `/exec`.
3. Разместите `vk-relay.mjs` под Node.js 24 за HTTPS на сервере в России. Укажите в окружении `VK_CALLBACK_SECRET`, `VK_CONFIRMATION_CODE`, `SHEETS_WEB_APP`, `SHEETS_KEY` и `QUEUE_PATH` на постоянном диске. `HOST` и `PORT` по умолчанию равны `127.0.0.1` и `8787`. Не включайте запись тел запросов в логи прокси.
4. В управлении сообществом настройте Callback API с адресом `https://ваш-домен/vk/callback` и секретом, включите `message_new` и `market_order_new`. Строку подтверждения ВК передайте в `VK_CONFIRMATION_CODE`.
5. В переменной `UTM_ALLOWLIST_JSON` задайте фактические значения кампаний, например `{"utm_source":["vk","yandex"],"utm_medium":["cpc"],"utm_campaign":["truck_mats"]}`. Значения вне списка не уходят в отчёт. Проверьте одной тестовой заявкой из ссылки с этими метками и одним тестовым заказом в ВК Маркете.

Для утверждения текстов согласия и политики у владельца сайта нужны реквизиты оператора и подтверждённые правила работы с заявками. Прямую отправку включают после утверждения этих текстов.
