# COMFORT 36 · установка на Рег.ру

Сайт уже собран. Для установки нужны ZIP с сайтом, шаблон `config.example.php` и код `GoogleSheets.gs`. На компьютере устанавливать программы не нужно. На хостинге используются PHP 8.3, модули `pdo_sqlite` и `curl`, а также планировщик CRON. Скриншот панели подтверждает сайт на тарифе «Хост-0» с PHP 8.3.

## 1. Сохраните старый сайт

1. В ispmanager откройте **Сайты**. Выберите `comfort-36.ru` и запомните корневую папку `/www/comfort-36.ru`.
2. В **Менеджере файлов** откройте `www`. Старая папка `comfort-36.ru` остаётся на сервере целиком. Дополнительно можно выделить её, нажать **Архивировать** и сохранить архив вне папок, доступных из браузера. В архив должны попасть и скрытые файлы, в том числе `.htaccess`, если он есть.
3. Если старый сайт использует базу данных, сохраняйте базу вместе со старой конфигурацией. В разделе **Базы данных** выберите её и сделайте экспорт в закрытую папку владельца. В планировщике CRON запишите, какие задания относятся к старому сайту.
4. Попросите поддержку Рег.ру подтвердить, что для существующего сайта можно сменить корневую папку без изменения DNS и SSL, если нужное поле в панели недоступно для редактирования.

[Резервное копирование у Рег.ру](https://help.reg.ru/support/hosting/rezervnoye-kopirovaniye-hostinga/bekapy)

## 2. Загрузите новый сайт в отдельную папку

1. В **Менеджере файлов** откройте `www` и создайте папку `comfort36-next` рядом с `comfort-36.ru`.
2. В новой папке нажмите **Загрузить** и выберите `COMFORT36-REG-RU.zip`. После загрузки выделите архив, нажмите **⋯ → Извлечь** и распакуйте его в эту же папку.
3. Проверьте, что на первом уровне `/www/comfort36-next` есть `index.html`, `cart.html`, `privacy.html`, папки `assets`, `media`, `thanks` и `api`. В папке `api` находится `comfort36-leads.php`.
4. Для проверки до переключения можно через **Сайты → Создать сайт** добавить временный поддомен, например `preview.comfort-36.ru`, с корнем `/www/comfort36-next` и PHP 8.3. Настройте ему HTTPS и добавьте его точный адрес в `origins` на следующем шаге. Если создание поддомена недоступно, подготовьте все файлы и настройки заранее, а тест на основном домене сделайте сразу после переключения. Обратное переключение описано в шаге 7.

[Загрузка архива через ispmanager](https://help.reg.ru/support/hosting/razmeshcheniye-sayta-otobrazheniye-v-brauzere/kak-razmestit-gotovyy-sayt-v-internete)

## 3. Настройте приём и почту

1. Из `www` поднимитесь на один уровень. Рядом с папкой `www` создайте `comfort36-private` с правами `700`. В этой папке будут настройки и база заявок. Файлы из неё должны быть недоступны по URL.
2. Загрузите туда шаблон `config.example.php` и переименуйте его в `config.php`. Установите права `600`. Откройте **Редактировать** и меняйте значения справа от `=>`, сохраняя кавычки и запятые.
3. Для `rate_key` вставьте случайную строку минимум из 32 символов. Например, откройте PowerShell на компьютере и выполните команду ниже.

   ```powershell
   $rng = [System.Security.Cryptography.RandomNumberGenerator]::Create()
   $bytes = New-Object byte[] 32
   $rng.GetBytes($bytes)
   [BitConverter]::ToString($bytes).Replace('-', '').ToLowerInvariant()
   $rng.Dispose()
   ```

4. В `mail_from` укажите действующий ящик на домене `comfort-36.ru`. Если такого ящика ещё нет, создайте его в разделе **Почта**. В `mail_to` укажите адрес, который реально проверяет менеджер. Поля `vk_token` и `vk_peer` оставьте пустыми.
5. В `origins` уже есть основной домен. Для временного поддомена впишите его через запятую в кавычках, например `'https://preview.comfort-36.ru'`, без завершающей косой черты. Сохраните файл.
6. Откройте **Планировщик CRON → Создать**. Выберите запуск каждую минуту. В команду вставьте путь к PHP и скрипту. Замените `LOGIN` на логин хостинга из карточки услуги. В менеджере файлов проверьте полный путь к новой папке. Команда выглядит так.

   ```sh
   /opt/php/8.3/bin/php -f /var/www/LOGIN/data/www/comfort36-next/api/comfort36-leads.php -- worker
   ```

   Если панель требует отдельно указать расписание, заполните все пять полей символом `*`. Если указанные на вашем сервере пути отличаются, возьмите фактический путь из панели или уточните его в поддержке. При ошибке доставки проверяйте журнал CRON и папку «Спам» получателя.

[Планировщик CRON на Рег.ру](https://help.reg.ru/support/hosting/php-asp-net-i-skripty/planirovshchik-cron)

## 4. Подключите Telegram

1. Откройте в Telegram `@BotFather`, отправьте `/newbot`, придумайте отображаемое имя и уникальное имя пользователя с окончанием `bot`.
2. Скопируйте токен из ответа BotFather прямо в закрытый `config.php`, в поле `telegram_token`. Токен нужен только здесь.
3. Если заявки принимает один человек, пусть откроет диалог с ботом и нажмёт **Запустить**. Для команды создайте закрытую группу, добавьте бота, разрешите ему отправлять сообщения и напишите `/start@имя_вашего_бота` в группе.
4. В Планировщике CRON создайте временное задание с запуском каждую минуту. Подставьте тот же `LOGIN` в команду ниже.

   ```sh
   /opt/php/8.3/bin/php -f /var/www/LOGIN/data/www/comfort36-next/api/comfort36-leads.php -- telegram-chats > /var/www/LOGIN/data/comfort36-private/telegram-chats.txt 2>&1
   ```

5. Подождите один цикл. В менеджере файлов откройте `comfort36-private/telegram-chats.txt`, найдите свой диалог или группу и скопируйте число из начала строки в `telegram_chat`. Минус у группового ID тоже копируйте. Отключите временное задание. Основное задание с `worker` оставьте активным.

По умолчанию Telegram получает номер заявки и источник, а полный текст приходит на рабочую почту. Для полного текста в Telegram см. шаг 6.

[Документация Telegram о создании бота](https://core.telegram.org/bots)

## 5. Подключите Google Таблицу

1. Создайте пустую Google Таблицу. Откройте **Расширения → Apps Script**. В файле `Code.gs` замените начальный код содержимым файла `GoogleSheets.gs` и сохраните проект.
2. Нажмите шестерёнку **Настройки проекта**. Внизу в разделе **Свойства скрипта** нажмите **Добавить свойство**. Имя `SHEETS_KEY`, значение — новая случайная строка минимум из 32 символов. Для неё можно повторить команду PowerShell из шага 3.
3. Вернитесь в редактор, в списке функций выберите `setupComfort36` и нажмите **Выполнить**. Подтвердите доступ к своей таблице. Появится лист **Лиды**.
4. Нажмите **Развернуть → Новое развертывание → Веб-приложение**. Укажите выполнение от своего имени и доступ **Все**, чтобы Рег.ру мог отправлять запросы без входа в Google. Сама таблица остаётся закрытой. Дайте доступ к ней только заказчику и его сотрудникам.
5. Скопируйте ссылку веб-приложения с окончанием `/exec` в поле `sheets_url` в закрытом `config.php`. В `sheets_key` вставьте точно то же значение, что записали в `SHEETS_KEY` в Apps Script.
6. В `utm_allowlist` впишите реальные значения кампаний из рекламных ссылок. Например, если ссылка содержит `utm_source=yandex&utm_medium=cpc&utm_campaign=truck_mats`, укажите `'utm_source' => ['yandex']`, `'utm_medium' => ['cpc']` и `'utm_campaign' => ['truck_mats']` в соответствующих строках. Остальные списки можно оставить пустыми и заполнить по мере добавления меток.

Лист **Лиды** показывает дату, источник заявки, разрешённые метки и ID. Для отдельного листа с именем, телефоном, комментарием и составом заявки см. следующий шаг.

[Развёртывание веб-приложения Apps Script](https://developers.google.com/apps-script/guides/web)

## 6. Полный текст в Таблице и Telegram

Первичная запись заявки, включая согласие, сохраняется на хостинге в России. Перед включением контактов в зарубежных сервисах владелец сайта должен утвердить политику и проверить требования к трансграничной передаче. До этого полный текст остаётся на рабочей почте, а Telegram и Таблица получают сведения без имени и телефона.

1. В папке `comfort36-next` откройте публичный файл `privacy-settings.js`. Заполните `operatorName`, `operatorDetails` и `operatorEmail` утверждёнными публичными реквизитами оператора. Ключи и токены в этот файл не вставляют.
2. Когда оператор подтвердит передачу в Google, задайте в свойствах Apps Script `ALLOW_CONTACT_DATA=true`. Снова выполните `setupComfort36`. Появится лист **Заявки с сайта**. В **Развернуть → Управление развертываниями** обновите развертывание до текущей версии кода, если до этого использовалась старая версия.
3. В `privacy-settings.js` установите `googleContacts: true` и затем в закрытом `config.php` установите `'sheets_include_contacts' => true`. Новая строка будет содержать имя, телефон, комментарий, состав заявки и UTM. Исправления после отправки обновляют эту же строку.
4. Если оператор также подтвердил передачу в Telegram, в `privacy-settings.js` установите `telegramContacts: true`, а в закрытом `config.php` — `'telegram_include_contacts' => true`. В бота будет приходить полный текст.

[Разъяснение Минцифры о локализации и трансграничной передаче](https://storage.yandexcloud.net/comply-publicfiles/public/Otvet_Mintsifry_12.05.2025_lokalizatsija.pdf)

## 7. Проверьте и переключите домен

1. Откройте временный поддомен, если вы его настроили. Пройдите путь с главной и из корзины. Используйте тестовое имя и номер своего сотрудника. Проверьте, что после формы открывается «Спасибо», данные совпадают, а исправление телефона принимается сервером.
2. Проверьте доставку на почту, в Telegram и в таблицу. Обычно это происходит в течение одного цикла CRON. Повторите тест со ссылкой, содержащей разрешённые UTM. Заявка появляется в очереди сразу после записи на хостинге. Сбой одного канала даёт повтор в этом канале.
3. В **Сайты → comfort-36.ru → Изменить** выберите корневую папку `/www/comfort36-next`, если поле доступно. Если оно заблокировано, обратитесь в поддержку Рег.ру с запросом сменить корень существующего сайта на эту папку и сохранить настройки домена и SSL. После переключения откройте `comfort-36.ru` в приватном окне браузера и повторите тест заявки.
4. Если понадобится откат, верните для `comfort-36.ru` корневую папку `/www/comfort-36.ru`. Старый сайт останется в ней вместе с исходными файлами. Папку новой сборки и закрытую базу заявок оставьте до решения владельца, чтобы уже полученные обращения сохранились.

Если вместо страницы «Спасибо» форма показывает ошибку, сначала проверьте путь к `config.php`, адреса в `origins`, наличие хотя бы одного полного канала, модули `pdo_sqlite` и `curl`, а также журнал PHP сайта. Для проверки интерфейса на GitHub Pages автоматическая отправка включается после появления рабочего HTTPS-адреса формы. Для сборки из исходников под Рег.ру используйте `BASE_PATH=/` и `VITE_LEAD_API_URL=/api/comfort36-leads.php`.
